# Visual Assets — Icons and Images

## The rule

**Never draw SVG icons in code. Never use SVG icon libraries.**

All icons are images (.png or .webp) generated by Gemini or ChatGPT (DALL-E).
This applies to every icon, illustration, and decorative image in the product.

---

## Why

- SVG icon libraries (Lucide, Heroicons, Phosphor, Feather, etc.) are recognizable.
  Every developer knows what a Lucide icon looks like. Using them makes the product
  look like it was assembled from parts, not designed.
- AI-generated image icons can be given a consistent artistic style that is unique to
  the product. They reinforce the visual anchor from the creative direction brief.
- Custom image icons signal craft, intent, and investment.

---

## How to generate icons

### Step 1: Define the icon style for the project

Write a **style prefix** that all icon prompts in this project will use. It encodes:
- Rendering style (flat, illustrated, 3D, hand-drawn, etc.)
- Color palette (use the project's brand colors or "monochrome")
- Background (transparent, white, or the product's surface color)
- Stroke, shadow, or texture level
- Mood alignment with the creative direction brief

**Example style prefixes:**

```
// For a premium studio operations product:
"Flat icon, single warm off-white stroke on deep olive-dark background,
 vector-clean geometric shapes, slight grain texture, no gradients,
 editorial and professional feel, 512x512, transparent background"

// For a data dashboard (technical, precise):
"Minimal line icon, single 2px black stroke, perfectly geometric,
 no fill, no drop shadow, Swiss-style precision, 512x512,
 transparent background"

// For a consumer lifestyle app (warm, illustrated):
"Soft illustrated icon, gentle rounded shapes, warm pastel fill with
 darker outline, friendly and approachable, slight paper texture,
 512x512, transparent background"
```

### Step 2: Write the icon prompt

```
[STYLE PREFIX] + [WHAT THE ICON DEPICTS]
```

**Examples:**
```
"Flat icon, single warm off-white stroke on deep olive-dark background,
 vector-clean geometric shapes, slight grain texture, no gradients,
 512x512, transparent background — a camera with a shutter aperture"

"Minimal line icon, single 2px black stroke, no fill, 512x512,
 transparent background — a calendar grid with one day highlighted"
```

### Step 3: Generate and export

- **Tool:** Gemini (Google) or ChatGPT (DALL-E 3 or later)
- **Resolution:** Generate at 512 × 512 px minimum. Export at 2× the display size:
  - Display 24px → export 48px
  - Display 32px → export 64px
  - Display 48px → export 96px
- **Format:** PNG with transparency (or WebP with alpha for smaller file size)
- **Naming:** `icon-[name]@2x.png` (e.g., `icon-camera@2x.png`)
- **Storage:** `public/icons/` or `src/assets/icons/` — consistent across the project

### Step 4: Use in code

```tsx
// Always provide alt text
<img src="/icons/icon-camera@2x.png" width={24} height={24} alt="كاميرا" />

// For decorative icons (purely visual, meaning conveyed by adjacent text):
<img src="/icons/icon-camera@2x.png" width={24} height={24} alt="" aria-hidden="true" />

// CSS sizing (use logical pixels, not percentages):
img.icon {
  width: 24px;
  height: 24px;
  object-fit: contain;
  flex-shrink: 0;
}
```

---

## Consistency rules

- **All icons in a project use the same style prefix.** Never mix styles.
- **All icons are the same pixel size** at the same use context (all nav icons 24px, all button icons 20px, etc.).
- **Regenerate** if a generated icon has visible artifacts, misaligned geometry, or looks inconsistent with the set.
- **Store the style prefix** in the project's README or a `docs/icon-style.md` so anyone can generate more icons.

---

## When a task requires a new icon

1. Load the project's existing icon style prefix.
2. Write the prompt: `[prefix] — [what the icon depicts]`.
3. Generate in Gemini or ChatGPT.
4. Export as PNG at 2× display size with transparency.
5. Place in `public/icons/` or `src/assets/icons/`.
6. Use `<img>` with correct `alt` text.
7. Add the icon name to the delivery report under "Assets added."

---

## Illustrations and decorative images

Same rule: AI-generated, not SVG drawn in code.

- Use the same style prefix as the icons for visual consistency.
- For scene illustrations, adjust the prompt to describe the composition:
  ```
  "[style prefix] — a wide scene of an empty photography studio at golden hour,
   soft light through large windows, equipment in background, editorial feel"
  ```
- Format: WebP (better compression) or PNG if transparency is needed.
- Provide `alt` text that describes the scene's meaning, not its content.

---

## What is NOT covered by this rule

- **CSS shapes:** `border-radius`, `clip-path`, or CSS geometric shapes are not icons — use them freely.
- **Charts and data visualizations:** these are rendered by code (SVG via D3, Recharts, etc.) — not icons.
- **Loading spinners:** pure CSS animations — not icons.
- **Inline decorative geometry:** a background gradient, a divider line, a progress bar — not icons.

The rule is specifically about **icons that represent actions, entities, or concepts** in the UI.
